# AIT V1.8 KMBox NET 测试报告

2026-11-27。Windows x64 候选包已构建。Phase 8 等待设备 A、设备 B 和实体 KMBox NET 的闭环验收。

## 构建与软件回归

- 使用 `-KmCalibration -AutoTracking` 构建 `VisionStudio-V1.8-Dual-Stage-Manual-Stop-windows-x64.zip`，包含主程序、KMBox 侧车、单步校准工具、设备 A 按键观察工具和 YOLO26s 模型。
- Vue 类型检查、生产构建、主程序及单步校准窗口启动自检通过。校准工具未注册键盘停止快捷键。已核对各可执行文件的 x64 架构以及 ZIP 的 SHA-256。
- 21 项 Rust 回归通过，覆盖源帧准星、四方向移动符号、阶段切换和同一 Track ID、目标死区、速度限制、松开任意一键及故障停止。
- 打包侧车的本机 UDP 回归通过，覆盖只按一键时不发送屏蔽命令、组合触发后的 ACK 门控、错误序号的 ACK、松键后忽略迟到的接管 ACK、恢复 ACK 丢失及重连优先解除屏蔽。
- 软件处理的 ACK 表示 KMBox 应答了对应命令。设备 A 上的物理 X/Y、五键透传以及软件相对位移需要分别观察。
- 本程序只改所属连接已知屏蔽值中的 BIT5 和 BIT6。KMBox NET SDK 没有公开读取其他客户端设置的屏蔽位的接口，因此本次使用 V1.8 独占盒子命令连接。[KMBox NET SDK 接口](https://github.com/kvmaibox/kmboxnet/blob/main/c%2B%2B_demo/NetConfig/kmboxNet.h)

设备 B 的 RTX 3060 已运行 TensorRT 推理并接收设备 A 的 640 × 640 NDI 画面。首个左键版的现场日志记录了两次屏蔽 ACK、119 条位移 ACK，以及在物理报文龄 1201 ms 和 1203 ms 停止后的两次解除屏蔽 ACK。期间视频帧和命令应答持续更新。用户观察到向左移动，日志中的锁定点与换算比例保持在 `(281.8, 335.8)` 和 `(0.269231, 0.269231)`，限速前位移为 `(-10, 4)`，实际下发为 `(-1, 0)`。日志没有包含目标偏右时的有效锁定样本。

左键 r2 保留跟随中的 1200 ms 报文保护。武装等待期间可以静置。正常松键需收到解除屏蔽 ACK 及有效的全松键状态，才返回等待左键。故障后保持锁止。位移取整保留了小数分量，方向切换和停止时清除相关余量。

左键 r2 现场复测时，操作员以设备 B 软件的 NDI 预览准星为参考，分别将目标置于准星左侧和右侧。按住物理左键时，两侧样本的跟随方向均正确。

## 双阶段实体设备验收

本轮使用物理左右键组合，保持 RTX 3060、YOLO26s、一个类别、一个目标、120 KMBox 单位/秒速度上限及最多 64 NDI 像素起始半径。用 P 核对方向，再用 PD 核对跟随。切换和过渡距离以源帧像素计，居中准星设为 50% / 50%。

| 检查项 | 通过条件 | 结果 |
| --- | --- | --- |
| 空闲、武装未触发 | 设备 A 的物理 X/Y 和按键照常工作，无 AI 位移 | 待测 |
| 按住左右键 | 接管 ACK 先于首条 AI 位移，设备 A 的物理 X/Y 不叠加，五键仍可监控和透传 | 双阶段包待测 |
| 四方向吸附 | 上、下、左、右的目标均可向对应方向移动 | 双阶段包待测 |
| 吸附转跟随 | 远处提高响应、近处减速。静止目标进入死区后停止发送，移动目标维持同一 Track ID | 双阶段包待测 |
| 松开任一键 | 停止位移，收到解除屏蔽 ACK，设备 A 的物理 X/Y 恢复。正常全松键回到等待组合键 | 双阶段包待测 |
| 手动停止与正常退出 | 每种情况均停止位移，并恢复设备 A 的物理 X/Y | 待测 |
| 切换设备 B 窗口 | 切换窗口后仍可用物理组合键触发，松开后恢复 | 待测 |
| 目标丢失、NDI 断流和帧超时、物理报文过期 | 停止位移，收到解除屏蔽 ACK，设备 A 的物理 X/Y 恢复 | 双阶段包待测 |
| KMBox 断连期间停止 | 显示「物理 X/Y 恢复待确认」，重连原盒子后先确认解除屏蔽 | 待测 |
| 至少 10 轮接管与恢复 | 每轮两次 ACK 和设备 A 实际行为对应，无旧位移或屏蔽残留 | 待测 |
