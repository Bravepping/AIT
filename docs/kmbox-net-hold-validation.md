# KMBox NET 静止长按专项验收

## SDK 与现场证据

公开 NET SDK 的 UDP 监听线程将物理鼠标和键盘数据写入本机缓存。五个 `kmNet_monitor_mouse_*` 函数检查监控状态后读取缓存中的按键位。`kmNet_monitor` 设置监控端口，命令应答与物理监控走不同的 UDP 接收路径。公开 SDK 没有给出独立的实时五键查询，也没有保证静止时按固定周期发送完整状态。[KMBox NET C++ SDK](https://github.com/kvmaibox/kmboxnet/blob/main/c%2B%2B_demo/NetConfig/kmboxNet.cpp) · [厂商监控示例](https://www.kmbox.top/wiki_doc/kmboxNet/site/python/)

现场日志中左键和右键的按下、释放都收到。右键静止持有期间，命令心跳有应答，但五键报文超过 1200 ms 未更新。这证明当次心跳与物理状态更新是两类事件。静止期间可能没有新 HID 报告，单凭客户端日志无法确定固件是否丢报，或在所有设备上只按事件发送。

## 测试包行为

- 只有匹配设备地址和监控报文长度的物理报告更新五键时钟。按键位完全相同也可以更新。监控心跳另计，超时时五键显示未知。
- 临近超时的有效报告优先转发给主程序。迟到的同掩码报告也会先经过超时锁止处理。连接恢复后，Dry Run 需要手动重新启用。
- 本包的主程序和 KMBox 侧车均锁定真实自动发送。设备 A 只需推送 NDI。支持普通桌面的独立手动单步校准。

## 设备 B 复测

1. 关闭其他 KMBox 监控程序，解压并运行 `VisionStudio.exe`，在「设备连接」连接盒子并开启监控。按随包 `README.md` 准备 WebView2、NDI 和推理运行库。
2. 每轮点击「记录 30 秒 UDP 报文」。在设备 A 的普通桌面静止按住左键约 5 秒，松开。右键和左右组合分别重复。组合分别松开左键和右键。只做物理按键操作。
3. 如果 NDI 和模型就绪，可在「鼠标控制」启用 Dry Run，选相应的按住热键方案。先确认按下时能出现候选，再观察静止时是否保持。出现「报文超时」时，记录时间并松开。等到新状态后手动重新启用。
4. 在「运行日志」找到 `KMBox 报文记录已保存`，提供该行指向的 `kmbox-wire-*.txt`。记录最多 30 秒或 50000 条，包含接收 UTC 时间、本地物理序号、五键掩码、鼠标字段、监控命令应答头、超时及断线。物理包的本地序号是接收计数。日志省略 UUID 和键盘数据。

若实体静止持有期间只有心跳应答，程序会在 1200 ms 后安全锁止。要让这种固件的静止长按持续，需厂商提供带当前五键状态的周期报告或可验证的读取接口，再验证失去释放报文时能安全停止。
